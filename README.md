# nbki_smoke_tester

Анализатор smoke-тестов
_______________________________________________________________________
Описание


Анализатор smoke-тестов — это утилита для автоматической проверки результатов загрузки тестовых XML-файлов.

Программа анализирует лог-файл loader-trace.log, сопоставляет фактические результаты обработки файлов со заданными ожиданиями, и формирует наглядный HTML-отчет с результатами тестирования.

Используется для быстрой валидации корректности обработки пакета тестовых данных без ручного разбора логов.
_______________________________________________________________________

Принцип работы


Есть набор тестовых XML-файлов в версии xsd-схемы 5.0, в каждом файле в атрибуте eventComment прописан ожидаемый результат: например: eventComment="EXP: ERROR, некорректный формат даты"

OK — ожидается успешная загрузка

ERR — ожидается ошибка (с уточнением)

WRONGBLOCK - ожидается ошибка с недопустимым блоком

NOTUPDATE или NOTFOUND - ожидается предупреждение

LASTRECORD - ожидается отказ в корректировке

ORG.XML.SAX.SAXPARSEEXCEPTION - ошибка валидации с XSD-схемой

Файлы загружаются через loader вручную

Loader формирует лог-файл: loader-trace.log, где фиксируются статусы обработки:

status: done 

status: reject


Программа читает выбранный пользователем временной интервал лог-файла, извлекает:

имя файла, фактический статус, сопоставляет с ожидаемым результатом из eventComment

Формируется HTML-отчет:

✅ PASS — результат совпал

❌ FAIL — результат не совпал
_______________________________________________________________________

Логика проверки результатов

Для каждого тестового файла программа сравнивает ожидаемый результат (из eventComment) с фактическим статусом из лога.

✅ Условия успешного прохождения (PASS)

Тест считается успешным, если:

в eventComment указано OK и в логе статус: done

или

в eventComment указано ERROR и в логе статус: rejected

❌ Условия ошибки (FAIL)

Тест считается проваленным, если:

в eventComment указано OK, но в логе: rejected

в eventComment указано ERROR, но в логе: done

или любое другое несоответствие ожидания и факта

🟡 Условия пропуска (SKIPPED)

Тест считается пропущенным, если:
в eventComment по какой-то причине оказалась пустая запись в логе
_______________________________________________________________________
Критическая ошибка


Если в выбранном временном интервале встречается сообщение RuntimeException, то дальнейший
анализ лога прерывается, и в отчете отображается сообщение о Критической ошибке лоадера
и времени ее записи в логе
_______________________________________________________________________
Фильтрация по имени файла

В обработку попадают только те записи из лога, которые:

соответствуют именам тестовых файлов, YP01MM000001_#######_######,  MM01MM000001_########_###### и присутствуют в анализируемом наборе

Это означает:

лишние записи в логе (другие процессы, старые файлы и т.д.) игнорируются

_______________________________________________________________________
Инструкция по использованию

1. Подготовка тестов

Подготовленные тестовые XML-файлы (версия XSD-схемы 5.0) необходимо скопировать в папку: rutdf

2. Получение лог-файла

Скачать актуальный лог текущих суток:

/opt/nbki/loader-manager/logs/loader-trace.log
3. Запуск программы

Запустить:

smoke.exe или Python-скрипт

4. Выбор лог-файла

В открывшемся окне:

указать путь к файлу loader-trace.log

5. Выбрать время начала анализа лога, т.е. время, с которого программа начнет обработку лога
(например, 08:45)

6. Выбрать время конца анализа лога, т.е. время, на котором программа закончит обработку лога
(например, 09:10)

5. Результат

После выполнения:

формируется HTML-отчет и автоматически открывается папка со сформированным файлом
